Changelog¶

The full changelog is maintained in the repository root at CHANGELOG.md.

Changelog¶

All notable changes to quantx-engine are documented here.

The format follows Keep a Changelog and this project adheres to Semantic Versioning: MAJOR.MINOR.PATCH. While the version is 0.x, a MINOR increment may change the API; PATCH increments are bug-fixes and packaging corrections only.

Unreleased¶

Added¶

  • quantx_engine.thermal (M6): finite temperature from Python, by ancilla purification on the block-sparse engine, for the XXZ, spin-1 Heisenberg and Hubbard chains. thermal.statics gives the energy, the local values, the correlations and the susceptibility from β = 0 up; thermal.structure_factor(...).spectrum() the dynamical structure factor S(k, ω, T); and thermal.current_correlation(...).conductivity() the optical conductivity Re σ(ω, T), by the Kubo formula. The ensemble is grand canonical, and the conventions are those of quantx_engine.models (S = σ/2). It is gated against an exact diagonalisation of the whole Hilbert space (test_thermal_ed.py): every quantity to the second-order Trotter error of the steps, below 1e-3 at the default step 0.05 and falling by 4 at half the step, and the Fourier transforms against Lehmann sums to 1e-8. J1-J2 and the Hubbard lattices have no purified form in the engine yet, and are refused. The C API entry point is qx_thermal.

Fixed¶

  • The finite-temperature current correlator ⟨J(t) J⟩_β lost weight at every time step. It applied J to the evolving state and compressed the product back to the bond cap, with a first sweep that truncated against a part of the chain that was not orthonormal: 3e-2 on a 4-site Hubbard chain at the exact bond dimension, whatever the step. It is now contracted exactly, as an MPO sandwich, and compressing an applied MPO (as for J|ψ⟩, also in the zero-temperature conductivity) brings the state to canonical form before it truncates.

  • The zero-temperature dynamics entry points (qx_tdvp_evolve, qx_spectral, qx_loschmidt and qx_conductivity) accept the type "xxz", as their error messages always said; they took only "heisenberg".

  • The exact Lieb–Wu energies in docs/hubbard_lieb_wu.csv, against which the Hubbard chain’s DMRG is compared, were off in the 7th digit (1.8e-7, 3.6e-7 and 7.3e-7 at U = 2, 4 and 8): the trapezoid rule that made them left an endpoint error from the integrand’s slope at ω = 0. They are made with Simpson’s rule now, and test_reference_data.py recomputes them independently, with the strong-coupling series checking its normalisation. The DMRG energies at N = 64 sit 8.4e-5, 4.6e-5 and 2.6e-5 from them.

0.1.0 — 2026-10-16 (first public release)¶

The first version published to PyPI. The native engine is now installable; what it can do from Python is gated against exact references.

Version numbers restart here, so the API stability guarantee of the internal 1.0.0 (below) does not carry over: as a 0.x release, any minor version may change the API.

Added¶

  • Platform wheels that carry the native engine (#194). There is one py3-none-<platform> wheel per platform, which serves every CPython 3: Linux x86_64 (manylinux_2_28), macOS arm64 and x86_64 (10.15+), and Windows AMD64. Any other platform installs the sdist, a pure-Python wheel that says so.

  • quantx_engine.models and dmrg.ground_state (#196): ground states of the XXZ, J1-J2, spin-1 Heisenberg and Fermi-Hubbard chains in a chosen symmetry sector on the block-sparse engine. They are gated against exact diagonalisation to 1e-10.

  • models.HubbardLattice and quantx_engine.hva (#197): Hubbard ground states on ladders, strips and cylinders, and fermionic HVA circuits on the same lattices (hva.circuit, hva.layout), returning energy, entanglement entropies and truncation. The circuits are gated against an independent state vector: to 1e-10 from a product start, and to 1e-6 from the default U = 0 start, which carries its DMRG preparation’s residual (measured at about 1e-8). Lattice DMRG is gated against exact diagonalisation on the geometries where the fermion signs are physical.

  • The native engine these sit on, built since the internal 1.0.0 (the git history has the details):

    • two-site DMRG on a block-sparse MPS that conserves U(1) or packed U(1)×U(1) charges, for any charge-conserving MPO, with a DMRG3S mixer;

    • SU(2)-symmetric DMRG for Heisenberg chains of any spin;

    • TDVP and TEBD;

    • finite-temperature statics and dynamics by purification;

    • Hubbard chains, ladders and cylinders, and fermionic HVA circuits;

    • a matrix-free Lindblad solver;

    • optional cuSOLVER acceleration in source builds.

    Only part of it is reachable from Python so far; the README lists which.

Changed¶

  • The README and the PyPI page lead with the engine: what it does from Python, and what each capability is checked against. Everything else in the package is marked experimental (M7). The package description now says the same thing.

Fixed¶

  • Shots on the native circuit backend were sampled from one random pass, so any randomness in the circuit made them unanimous.

    • Measured circuits: a measured Bell pair read 00 on all 1000 shots, as did every QASM program that ends in measure. When every measurement is terminal and no noise acts, the shots are now sampled from the state before measurement: the exact distribution, still from one pass. An observable with X or Y on a measured qubit then reads 0.

    • Noise: |1> under DepolarizingNoise(0.5) read all 0 or all 1, never the mixed state’s 3/4. With noise, or a measurement that later gates depend on, every shot now runs its own pass. This costs one full pass per shot, and expectation_exact becomes the average over the passes.

    • With shots = 0, a noisy circuit still returns one random pass.

    • The classical register and the returned state come from one pass.

    • A noise channel at strength zero counts as no noise.

    • max_shots (1 000 000) is now enforced, not only advertised. A shot count must be a non-negative integer, and one past 2³² is refused: 2³² + 10 used to wrap to 10 shots.

    • Amplitude damping runs in place, which makes the noisy per-shot path about three times faster (a 16-qubit GHZ circuit at 1000 shots: 47 s, from about 150 s).

  • The native depolarizing channel applied a random Pauli with probability p, which is (1 − p)ρ + (p/3)(XρX + YρY + ZρZ). DepolarizingNoise documents, and the density-matrix simulator in primitives runs, (1 − p)ρ + p·I/2. The native backend now runs the documented channel too. Two readers of the parameter were also wrong:

    • hardware.calibration_to_noise_model passed a gate’s average infidelity r as p. It now inverts the channel for the gate’s arity: p = 2r for a one-qubit gate, and about 5r/6 for a two-qubit gate, where the channel acts on both qubits. The worst gate sets p.

    • noise_char’s process-tomography fit used the average-gate factor (d + 1)/d where the depolarizing parameter needs d²/(d² − 1). It read DepolarizingNoise(0.1) back as 0.1125.

    PEC’s from_depolarizing keeps its Pauli-error parameter and now says how it maps: DepolarizingNoise(p) is noise_prob = 3p/4.

  • The native circuit backend returned ⟨Y⟩ with the wrong sign, exact and sampled alike: S H|0⟩ = |+i⟩ read −1. Every observable with an odd number of Y factors had its sign flipped, and so did any energy with such terms (a real Hamiltonian has none). The statevector, Lindblad and MPS code already used the right sign.

  • The Python simulators read noise models on their own terms. The density-matrix simulator in primitives (behind Estimator, Sampler and noise_vqe):

    • put noise only on the qubits a gate acts on;

    • never applied ReadoutNoise’s bit flip;

    • took T1 decay from noise_metadata, and only when amplitude_damping_gamma was unset.

    The dynamic-circuit simulator treated amplitude damping as a depolarizing probability and dropped every other channel. Now all three simulators apply the same channels, resolved by the new noise.native_channels: every qubit after every gate, as on the native backend, each rate clamped to [0, 1] as the backend clamps it. For dynamic circuits, DynamicResult.metadata reports noise_channels in place of the old p_noise. The density-matrix simulator now applies gates by contracting over their qubits, and one-qubit channels block by block, instead of multiplying 2^n x 2^n matrices: a two-layer, 8-qubit circuit with depolarizing and T1 noise takes 0.2 s, from 1.2 s, although every qubit now gets the noise.

  • The block engine’s lossless centre moves padded every bond they crossed with zero-weight states, so reported bond dimensions were inflated (a circuit capped at max_bond 4 reported 10). Energies and entropies were unaffected (#197).

  • CompositeNoise no longer drops a channel silently (#198). to_dict() merged its models with dict.update, so a second noise-kind model replaced the first: CompositeNoise([DepolarizingNoise(...), ThermalRelaxationNoise(...), ReadoutNoise(...)]) ran depolarizing + bit-flip with no T1 channel. Two models that emit the same key (noise, depolarizing_prob, amplitude_damping_gamma, noise_metadata, …) now raise NoiseModelError when the composite is built, including through +. So does a custom model’s noise selector of kind depolarizing or amplitude_damping that carries a value, next to DepolarizingNoise or AmplitudeDampingNoise: the keys differ, but the backend writes the selector’s value into the same field. Depolarizing and amplitude damping still combine with one noise-kind model.

  • ReadoutNoise’s docstring said its bit flip follows each measurement. The backend applies it to every qubit after every gate except measurements, so it is gate noise, not a readout error (#198).

  • Eigen 3.4.0’s BDCSVD can read out of bounds on some rank-deficient blocks. It crashed the DMRG’s single-site splits, which since use JacobiSVD, and the HVA centre moves before #197. The wheels build without LAPACKE, so the two-site DMRG, the dense DMRG, TDVP and the SU(2) DMRG still ran it. The build now applies Eigen 3.4.1’s two BDCSVD fixes to Eigen 3.4.0: that case reports a numerical issue, and the total-deflation test uses |col0|. The engine redoes any SVD that BDCSVD reports as failed with JacobiSVD, and a new test (qx_robust_svd_test) drives that path. The build stays on 3.4.0, the version the engine was validated with, and takes only these two fixes from 3.4.1.

  • The DMRG C API failed on every odd-length Heisenberg chain, with an error that blamed max_bond (#196).

  • An unknown model type in qx_dmrg_sweep silently ran as an empty Hamiltonian and returned E = 0; it is now an error (#196).

  • At n = 2 the five DMRG and dynamics entry points of the C API returned an internal error from inside the block engine, which needs n ≥ 3. qx_dmrg_sweep and qx_tdvp_evolve now answer 2-site chains with their dense and non-block solvers; the other three refuse with a message that says why (#195).

  • Four tutorial notebooks called APIs that do not exist, and printed claims their own outputs contradicted (#195).

Known issues¶

  • The VQE showcase’s measured bond dimensions are overstated. They were recorded before the #197 fix, so they are upper bounds. This covers docs/universal_mpo.md, the chi_used columns of docs/vqe_hubbard.csv, vqe_entanglement.csv and vqe_ladder.csv, and the chi column of vqe_width.csv. Configured χ (caps, the lossless budgets in vqe_barren_size.csv) are unaffected, and so are the energies, entropies and truncation errors.

Development history before the first public release¶

The versions below were internal milestones of the project. None was published to PyPI, and none has a release tag (an old v0.2.0 tag, which published nothing, was deleted before the first release). They are kept as a record of what was built and when. Version numbering restarts at 0.1.0 with the first public release.

1.0.0 (internal) — 2026-05-25 (Phase 2 complete)¶

Added¶

  • M167 — Benchmark suite: benchmarks/compare_backends.py covering Lanczos, Lindblad, DMRG, TEBD, VQE, QEC; JSON result artefacts; benchmarks-ci.yml workflow.

  • M168 — GPU wheels: quantx-engine[gpu] optional extra (CuPy-cuda12x runtime); gpu-wheels.yml CI with mock unit tests and optional self-hosted CUDA smoke test.

  • M169 — IBM Quantum real hardware round-trip: IBMHardwareBackend.submit, HardwareJob.fetch; examples/ibm_hardware_demo.py; 17 mock tests; hardware-tests.yml CI with gated real-hardware job (requires QISKIT_IBM_TOKEN).

  • M170 — quantx_engine.ibm: circuit_to_qasm3, QASM 3.0 serialisation compatible with Qiskit 1.x Primitives V2.

  • M171 — Community infrastructure: GitHub issue templates (bug, feature, question), PR template, SECURITY.md (private vulnerability reporting), CODE_OF_CONDUCT_CN.md (Contributor Covenant 2.1), expanded CONTRIBUTING.md, docs/add_your_hamiltonian.md contributor guide.

  • M172 — v1.0.0 release: version bump to 1.0.0, release.yml automated PyPI + GitHub Release workflow, API stability guarantee (see table below).
