Quantum Algorithms¶

Modules implementing quantum algorithmic primitives.

Quantum Walks¶

Continuous-time and discrete-time quantum walk simulation.

Quantum walk algorithms for the QuantX engine (M100).

Two walk models are provided:

DiscreteTimeWalk — coined quantum walk on an undirected graph. The walker lives in a joint coin ⊗ position Hilbert space. One step applies a coin operator (Hadamard, Grover, or custom) followed by a conditional shift. Efficient for cycle graphs, complete graphs, and hypercubes; extensible to arbitrary adjacency matrices.

ContinuousTimeQuantumWalk (CTQW) — Hamiltonian is the graph Laplacian (or adjacency matrix). State evolves as |ψ(t)⟩ = exp(−iHt)|ψ₀⟩ via Krylov exponentiation (no full diagonalisation for large graphs).

GroverWalk — marks one or more target nodes and uses the quantum walk to achieve quadratic speedup over classical random search. Returns the first step at which the marked-node probability exceeds a threshold (hitting time).

Quick start:

import numpy as np
from quantx_engine.contrib.quantum_walk import DiscreteTimeWalk, ContinuousTimeQuantumWalk

# Discrete walk on a 16-node cycle, 20 steps
walk = DiscreteTimeWalk.cycle(n=16, coin="hadamard")
result = walk.run(steps=20)
print(result.position_probs)      # shape (16,)

# Continuous walk on the same cycle
ctqw = ContinuousTimeQuantumWalk.from_adjacency(walk.adjacency)
result_c = ctqw.run(t=5.0)
print(result_c.position_probs)

Physical validation¶

Continuous-time quantum walk on a cycle of N nodes: probability P(0->k,t) = |J_k(2t)|^2 in the large-N limit (Bessel function), where J_k is the k-th order Bessel function of the first kind [Aharonov1993]. Discrete-time Grover walk: quadratic speedup for finding a marked vertex [Grover1996]; amplitude at the marked vertex grows as O(1/sqrt(N)) steps.

Quantum Signal Processing & QSVT¶

QSP angle sequences, qubitization, quantum singular value transformation.

M123: Quantum signal processing (QSP) and quantum singular value transformation (QSVT).

Quantum Signal Processing¶

For a scalar signal x ∈ [-1, 1] and a degree-d polynomial P(x) satisfying |P(x)| ≤ 1, the QSP circuit realises the transformation

U_QSP(x, Φ) = e^{iφ₀Z} ∏ₖ [ Wx · e^{iφₖZ} ]

where Wx = [ x, i√(1-x²) ]

[ i√(1-x²), x ]

is the signal unitary and Φ = (φ₀, …, φ_d) are the phase angles.

Quantum Singular Value Transformation¶

QSVT extends QSP to matrices: given a block-encoding U_A of an operator A, QSVT realises polynomial transformations P(A/‖A‖) via a sequence of controlled-phase rotations interleaved with queries to U_A and U_A†.

QSPAnglesFinder

Compute QSP phase angles for standard polynomial targets (sign, threshold, Chebyshev, Hamiltonian-simulation).

QSVTCircuit

Build and simulate QSVT circuits given phase angles and a block-encoding.

Physical validation¶

Chebyshev polynomial approximation of sign function: maximum deviation from sign(x) bounded by 2*exp(-2*(k-1)^2/(2k-1)) for degree-k approximation. QSP phases reproduce polynomial values to within 1e-6 for degree <= 8 (verified against scipy.special.chebyt in test suite).

class quantx_engine.contrib.qsp_qsvt.QSVTCircuit(phases, block_encoding, n_signal, alpha=1.0)[source]¶

Bases: object

Build and simulate a QSVT circuit given phase angles and a block-encoding.

QSVT applies a polynomial transformation P(σᵢ) to the singular values σᵢ of an operator A, where A is embedded as the top-left block of a unitary block-encoding U_A:

⟨G|U_A|G⟩ = A / α (‖A‖ ≤ α)

The QSVT circuit interleaves queries to U_A (and U_A†) with single-qubit Z-rotation projectors controlled on the block flag qubit:

U_QSVT = Π̃_{φ₀} ∏_{k=1}^{d} [ U_A · Π_{φₖ} ] (even d)

where Π_φ = e^{iφ|0⟩⟨0|} ⊗ I_A is a reflection through the signal subspace.

Parameters:

  • phases (array-like, shape (d+1,)) – QSP phase angles Φ.

  • block_encoding (array-like or callable) – Either a 2m × 2m unitary U_A (dense matrix) or a callable U_A(state) → state for larger spaces.

  • n_signal (int) – Dimension of the signal (block) subspace (= n_qubits of A).

  • alpha (float) – Block-encoding normalisation factor (‖A‖ ≤ alpha).

Dynamic Simulation¶

Hamiltonian simulation with adaptive step-size control.

Dynamic circuits with mid-circuit measurement and classical feed-forward — M86.

Provides:

  • DynamicCircuit: circuit IR supporting mid-circuit measurement, classical-register feed-forward, qubit reset, and bounded repeat-until-success loops.

  • DynamicSimulator: statevector trajectory simulator — runs shots independent trajectories, collapses the wavefunction on each measurement, and applies conditional gates according to the classical register state.

  • DynamicResult: result container with counts, quasi-probabilities, and classical-register snapshots.

Qubit/classical-bit ordering matches the primitives module: qubit 0 = LSB of the statevector index; bitstrings are printed MSB-first (qubit n-1 … qubit 0).

Quick reference:

from quantx_engine.contrib.dynamic import DynamicCircuit, DynamicSimulator

# Teleportation / feed-forward demo:
# Prepare |+⟩ on qubit 0, entangle 0-1, measure 0 → conditionally correct 1.
circ = (
    DynamicCircuit(n_qubits=2, n_cbits=1)
    .h(0)
    .cx(0, 1)
    .measure(0, 0)
    .if_bit(cbit=0, value=1, name="x", qubits=[1])
)
result = DynamicSimulator(shots=200, seed=0).run(circ)
# qubit 1 should always end up in |+⟩ ≡ (|0⟩+|1⟩)/√2, so counts ≈ 50/50
print(result.counts)

class quantx_engine.contrib.dynamic.DynamicSimulator(noise_model=None, shots=1, seed=None)[source]¶

Bases: object

Statevector trajectory simulator for dynamic circuits.

Each shot is an independent wavefunction trajectory. Mid-circuit measurements probabilistically collapse the wavefunction; conditional gates are applied based on the resulting classical register state.

Parameters:

  • noise_model – Optional NoiseModel instance. When set, its channels act on every qubit after every gate, as on the native circuit backend (native_channels(): depolarizing, amplitude damping, bit and phase flips, T1/T2 decay). Each shot is one trajectory, so the noise is sampled as random Pauli kicks and quantum jumps and every trajectory stays a pure state.

  • shots (int) – Number of independent trajectories to run.

  • seed (int | None) – Random seed for reproducibility.

Example

circ = DynamicCircuit(2, 2).h(0).cx(0, 1).measure_all()
result = DynamicSimulator(shots=500, seed=0).run(circ)
print(result.counts)   # {"00": ~250, "11": ~250}

Parameter Sweep¶

Variational parameter landscape scanning.

Parallel parameter sweep utilities for QuantX.

Run any callable (solver, circuit, QML training loop) over a grid of parameters using Python’s concurrent.futures for CPU-bound parallelism.

Usage:

from quantx_engine.contrib.sweep import ParameterSweep, SweepResult, grid_sweep

# Simple grid sweep over two parameters
def my_solver(J, h):
    # ... run simulation ...
    return {"energy": -J - h}

sweep = ParameterSweep(fn=my_solver, n_workers=4)
result = sweep.run({"J": [0.5, 1.0, 2.0], "h": [0.0, 0.5, 1.0]})
df = result.to_dataframe()   # pandas if available, else list of dicts
