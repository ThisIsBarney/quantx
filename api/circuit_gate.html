Circuit & Gate-Model¶

Modules that deal with gate-model circuits, transpilation, hardware backends, and QASM import/export.

Adapters¶

Unified execution adapter for Qiskit / Cirq-style backends.

Circuit adapters for Google Cirq and Amazon Braket (M77).

Converts between QuantX GateOp lists and the native circuit objects of each framework.

Both directions are supported:

# QuantX → Cirq
from quantx_engine.adapters import to_cirq, from_cirq
cirq_circ = to_cirq([GateOp("h", [0]), GateOp("cx", [0, 1])])
back      = from_cirq(cirq_circ)

# QuantX → Braket
from quantx_engine.adapters import to_braket, from_braket
bk_circ = to_braket([GateOp("h", [0]), GateOp("cnot", [0, 1])])
back    = from_braket(bk_circ)

All imports of cirq and braket are deferred so that the rest of QuantX remains importable even if those packages are not installed. AdapterError is raised when a required package is missing or a gate is not supported.

Transpiler¶

Hardware-aware circuit transpilation (M76).

Three main components:

CouplingMap — hardware qubit connectivity (undirected graph). Factory methods for common topologies: linear(), ring(), grid(), all_to_all(). Provides BFS shortest-path for routing.

HardwareTranspiler — compiles a circuit (list of GateOp) to a target device:

  1. Gate decomposition — rewrites non-native gates into the device’s native gate set ({CX+Rz} or {CZ+Rz}).

  2. SWAP insertion — moves logical qubits to physically-adjacent positions before each non-adjacent two-qubit gate (greedy path-following algorithm).

  3. Peephole optimisation (optimization_level ≥ 2) — cancels adjacent inverse-gate pairs and redundant SWAP·SWAP sequences.

TranspileResult — reports the transpiled circuit, logical→physical qubit map, number of inserted SWAPs, and gate/depth metrics.

Quick start:

from quantx_engine.transpiler import (
    CouplingMap, GateOp, HardwareTranspiler,
)

dev = CouplingMap.linear(3)            # 0-1-2
circ = [GateOp("cx", [0, 2])]          # non-adjacent CX: needs SWAP
transpiler = HardwareTranspiler(dev, native_gates="cx_rz")
result = transpiler.transpile(circ)
print(result.n_swaps)                  # 1

Hardware-aware circuit transpiler.

>>> result = t.transpile([GateOp("cx", [0, 2])])

QASM Import/Export¶

OpenQASM 3.0 parser and transpiler for the QuantX engine.

Converts a subset of OpenQASM 3.0 source into the QuantX native circuit JSON schema, suitable for passing to Engine.run_circuit().

Supported: - OPENQASM 3.0 / OPENQASM 3 header - qubit[n] name; / qubit name; register declarations - bit[n] name; / bit name; classical bit declarations - Standard gate applications (h, x, y, z, s, t, sdg, tdg, cx, cy, cz, ccx,

rx, ry, rz, p, u1, u2, u3, swap, iswap, id, reset)

  • Parameterized gates: rx(pi/2) q[0];

  • Measurements: c[0] = measure q[0]; / measure q[0] -> c[0];

  • Barrier statements (no-op in QuantX circuit)

  • Include directives (silently ignored)

  • Gate definitions (silently ignored)

  • Line comments // …

  • Block comments /* … */

Not supported (raises ParseError): - Classical control flow (if / while) - Subroutines / defcalgrammar - Delay / duration types - Pulse-level constructs

Cross, A. W. et al. (2022). OpenQASM 3: A broader and deeper quantum assembly language. ACM Trans. Quantum Comput. 3, 1–50. https://doi.org/10.1145/3505636

Circuit Templates¶

Parameterised ansatz circuits (hardware-efficient, UCCSD, …).

Circuit Templates Library — M88.

Provides a collection of standard parameterized quantum circuit ansätze and fully-fixed circuit templates, all returning circuit dicts compatible with the Estimator and Sampler primitives.

Quick reference:

from quantx_engine.templates import hardware_efficient_ansatz, ghz_circuit

# Parameterized HEA on 4 qubits, 2 layers
tmpl = hardware_efficient_ansatz(4, n_layers=2)
bound = tmpl.bind([0.1] * tmpl.n_parameters)
# bound is a plain circuit dict ready for Estimator/Sampler

# Fixed GHZ circuit (no parameters)
ghz = ghz_circuit(3)
circuit_dict = ghz.to_circuit()

quantx_engine.templates.uccsd_ansatz(n_electrons, n_qubits)[source]¶

Minimal UCCSD-inspired ansatz for quantum chemistry.

Structure: 1. Hartree-Fock reference: X gates on the first n_electrons qubits

(occupying the lowest orbitals).

  1. Single excitations: For each pair (p, q) with p < n_electrons and q >= n_electrons, a parameterized RY rotation that mixes occupied and virtual orbitals.

  2. Double excitations (simplified): For each pair of single-excitation pairs ((p, q), (r, s)) taken in order, a CNOT + RZ + CNOT sequence on qubits q and s (the virtual orbitals).

This is a simplified approximation suitable for testing/demonstration, not a rigorous UCCSD implementation.

Parameters:

  • n_electrons (int) – Number of electrons (occupied orbitals). Must satisfy 1 <= n_electrons < n_qubits.

  • n_qubits (int) – Total number of spin-orbital modes (qubits). Must be >= 2.

Return type:

CircuitTemplate

Hardware Backend¶

Generic hardware topology and noise model.

Real hardware backend integration — M93.

Provides abstractions for submitting QuantX circuits to real quantum hardware and pulling standardised calibration data, without tying callers to any single vendor SDK.

Classes¶

  • HardwareError — base exception for this module.

  • BackendCalibration — standardised calibration (T1, T2, gate errors, coupling map). Converts to a QuantX NoiseModel and CouplingMap.

  • HardwareJobResult — completed-job result (counts, probabilities).

  • HardwareJob — non-blocking async job handle with status polling.

  • IBMHardwareBackend — extends the existing IBMQuantumBackend with async submission, calibration fetching, and pulse-schedule submission.

  • IonQBackend — IonQ Cloud REST API (v0.3) backend; uses only urllib.request from the standard library.

  • GoogleBackend — Google Quantum AI backend via cirq-google (lazy import).

Functions¶

  • calibration_to_noise_model() — convert a BackendCalibration to a QuantX ThermalRelaxationNoise (or CompositeNoise when gate errors are large).

  • available_backends() — scan environment variables for configured backends and return a summary dict.

Qiskit V2 Primitives¶

Estimator + Sampler hardware-agnostic primitives — M85.

Provides:

  • SparsePauliOp: lightweight observable specification (Pauli tensor products with complex coefficients).

  • Estimator: compute ⟨ψ|O|ψ⟩ expectation values for circuits and observables, with optional noise and shot sampling.

  • Sampler: sample quasi-probability distributions from circuits.

  • EstimatorResult, SamplerResult: typed result containers.

Both primitives use a pure-NumPy statevector simulator (noiseless default) or a density-matrix simulator when a NoiseModel is supplied. No C++ engine binary is required.

Qubit ordering convention (same as Qiskit): qubit 0 is the least-significant bit of the statevector index. Pauli strings are written MSB-first, so "ZI" means Z on qubit 1, I on qubit 0 (matching the index ordering of the computational basis ket |q1 q0⟩).

Quick reference:

from quantx_engine.primitives import Estimator, Sampler, SparsePauliOp

bell = {
    "n_qubits": 2,
    "operations": [
        {"name": "h",  "qubits": [0]},
        {"name": "cx", "qubits": [0, 1]},
    ],
}

# Exact expectation value  ⟨Bell|ZZ|Bell⟩ = 1
result = Estimator().run([bell], [SparsePauliOp("ZZ")])
print(result.values)  # [1.]

# Probability distribution (exact)
sresult = Sampler().run([bell])
print(sresult.quasi_dists[0])  # {0: 0.5, 3: 0.5}  (|00⟩ and |11⟩)

References

[1]

Qiskit Community (2023). Qiskit: An open-source framework for quantum computing. Zenodo. https://doi.org/10.5281/zenodo.2573505 (Estimator/Sampler V2 primitives specification)

[2]

Bravyi, S. & Gosset, D. (2016). Improved classical simulation of quantum circuits dominated by Clifford gates. Phys. Rev. Lett. 116, 250501. https://doi.org/10.1103/PhysRevLett.116.250501
