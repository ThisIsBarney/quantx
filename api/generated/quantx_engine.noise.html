quantx_engine.noise¶

Noise model library for the QuantX engine.

Provides structured noise configuration objects that generate the JSON noise payloads accepted by Engine.run_circuit() and Engine.run_qasm().

Noise fields are placed on the circuit dict (not in options):

from quantx_engine.noise import DepolarizingNoise circuit = engine.parse_qasm(src, shots=1000) circuit.update(DepolarizingNoise(0.01).to_dict()) # add noise to circuit engine.run_circuit(circuit)

Supported noise models and their native backend mapping: - DepolarizingNoise — emits top-level depolarizing_prob (fully supported) - AmplitudeDampingNoise — emits top-level amplitude_damping_gamma (fully supported) - ThermalRelaxationNoise— emits noise={kind:t1_decay,...} for T1; T2 dephasing

is stored in noise_metadata (informational only — native backend does not yet apply T2 dephasing)

  • ReadoutNoise — emits noise={kind:bit_flip,prob:p} (supported as

    bit-flip channel, not measurement-specific readout)

  • CompositeNoise — combine models whose fields are disjoint: at most one

    noise-kind model, and any shared field raises

References

[1]

Nielsen, M. A. & Chuang, I. L. (2000). Quantum Computation and Quantum Information. Cambridge University Press. https://doi.org/10.1017/CBO9780511976667 (Depolarising, amplitude damping, phase flip channels: Ch. 8)

[2]

Lindblad, G. (1976). On the generators of quantum dynamical semigroups. Commun. Math. Phys. 48, 119. https://doi.org/10.1007/BF01608499

[3]

Preskill, J. (1998). Lecture Notes on Quantum Information. Available at http://theory.caltech.edu/~preskill/ph229/

Physical validation¶

Depolarising channel: p(I)=1-3p/4, p(X)=p(Y)=p(Z)=p/4 leaves the maximally mixed state rho=I/2 invariant for all p [Nielsen&Chuang, Ch. 8.3]. Amplitude damping: excited state |1> decays with probability gamma; p_|1>(t) = exp(-gamma*t) [exponential Markovian decay].

class quantx_engine.noise.DepolarizingNoise(prob)[source]¶

Bases: NoiseModel

Uniform depolarizing channel applied after every gate.

The depolarizing channel replaces the qubit state with the maximally mixed state with probability p: ρ → (1-p)ρ + p·I/2, which is (1 - 3p/4)ρ + (p/4)(XρX + YρY + ZρZ). The native circuit backend applies it to every qubit after every gate (idle qubits included), one trajectory per shot. The density-matrix simulator in quantx_engine.primitives and the dynamic-circuit simulator apply it the same way (see native_channels()).

Parameters:

prob (float) – Depolarizing probability per gate, in [0, 1].

class quantx_engine.noise.ThermalRelaxationNoise(T1, T2, t_gate=50.0)[source]¶

Bases: NoiseModel

Combined T1/T2 thermal relaxation noise model.

Computes amplitude damping γ = 1 − exp(−t_gate / T1) from the longitudinal relaxation time T1 and gate duration t_gate. The T2 dephasing parameter λ = 1 − exp(−t_gate / T2) is computed and stored in the output dict under noise_metadata for informational purposes, but is not currently consumed by the native circuit backend (which supports T1 amplitude damping only via the t1_decay noise kind).

to_dict() emits {"noise": {"kind": "t1_decay", "T1": T1, "dt": t_gate}, "noise_metadata": {...}} — only the noise sub-dict is executed.

The constraint T2 ≤ 2·T1 (Lindblad bound) is enforced.

Parameters:

  • T1 (float) – Longitudinal relaxation time in nanoseconds.

  • T2 (float) – Transverse relaxation time in nanoseconds. Must satisfy T2 ≤ 2·T1.

  • t_gate (float) – Gate duration in nanoseconds (default: 50 ns, typical for superconducting qubits).

class quantx_engine.noise.ReadoutNoise(prob)[source]¶

Bases: NoiseModel

Symmetric bit-flip noise, intended to stand in for readout errors.

The native circuit backend implements this as a bit_flip channel (noise = {"kind": "bit_flip", "prob": p}): after every gate except a measurement, each qubit flips with probability p. So it acts as gate noise, not as a readout error. A true readout error model would act on the measurement outcomes only; bit_flip is the closest mechanism the backend supports.

Parameters:

prob (float) – Bit-flip probability per qubit per gate, in [0, 0.5]. Values above 0.5 are anti-correlated and should be modeled differently.

class quantx_engine.noise.CompositeNoise(models)[source]¶

Bases: NoiseModel

Combination of multiple noise models applied simultaneously.

to_dict() is the union of the models’ payloads, so the models must emit disjoint keys. If two models emit the same key, building the composite (constructor or +) raises NoiseModelError; no entry is ever silently replaced.

In practice this allows at most one noise-kind model per composite. ThermalRelaxationNoise (t1_decay) and ReadoutNoise (bit_flip) both put their channel under the single key noise, because the native backend parses exactly one noise object per circuit (parse_noise_config in src/json_utils.cpp). A second one has no slot to go to: merging the two would drop a channel. DepolarizingNoise and AmplitudeDampingNoise emit the top-level fields depolarizing_prob and amplitude_damping_gamma, which the backend applies alongside the noise channel, so they combine with each other and with one noise-kind model:

CompositeNoise([DepolarizingNoise(0.005),
                ThermalRelaxationNoise(T1=1e5, T2=6e4, t_gate=50)])  # ok
CompositeNoise([ThermalRelaxationNoise(T1=1e5, T2=6e4, t_gate=50),
                ReadoutNoise(0.02)])     # NoiseModelError: both emit "noise"

Every key is checked, not only noise. Each top-level field holds one value per circuit, so two DepolarizingNoise models collide on depolarizing_prob (build one model instead). noise_metadata is checked as well: no simulator executes it, but a merge would keep only one model’s description.

The check is on the fields a payload sets, not only on its keys. A noise selector of kind depolarizing or amplitude_damping (no shipped model emits one, but the backend accepts both, so a custom model may) is another spelling of depolarizing_prob or amplitude_damping_gamma: the backend writes its prob or gamma (at the selector’s top level or in its params) into that field. Such a selector therefore collides with a DepolarizingNoise or AmplitudeDampingNoise although the keys differ. A selector that carries no value leaves the field alone, and combines.

Parameters:

models (list[NoiseModel]) – List of NoiseModel instances to combine.

Raises:

NoiseModelError – If models is empty, holds a non-NoiseModel, or two models set the same field: they emit the same key, or one emits a noise selector that the backend writes into another’s field.
