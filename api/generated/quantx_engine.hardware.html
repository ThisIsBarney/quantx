quantx_engine.hardware¶

Real hardware backend integration — M93.

Provides abstractions for submitting QuantX circuits to real quantum hardware and pulling standardised calibration data, without tying callers to any single vendor SDK.

Classes¶

  • HardwareError — base exception for this module.

  • BackendCalibration — standardised calibration (T1, T2, gate errors, coupling map). Converts to a QuantX NoiseModel and CouplingMap.

  • HardwareJobResult — completed-job result (counts, probabilities).

  • HardwareJob — non-blocking async job handle with status polling.

  • IBMHardwareBackend — extends the existing IBMQuantumBackend with async submission, calibration fetching, and pulse-schedule submission.

  • IonQBackend — IonQ Cloud REST API (v0.3) backend; uses only urllib.request from the standard library.

  • GoogleBackend — Google Quantum AI backend via cirq-google (lazy import).

Functions¶

  • calibration_to_noise_model() — convert a BackendCalibration to a QuantX ThermalRelaxationNoise (or CompositeNoise when gate errors are large).

  • available_backends() — scan environment variables for configured backends and return a summary dict.

Standardised device calibration snapshot.

All time constants are in nanoseconds (consistent with ThermalRelaxationNoise).

Parameters:

  • backend_name (str) – Human-readable name of the device (e.g. "ibm_sherbrooke").

  • n_qubits (int) – Total number of physical qubits.

  • t1 (dict[int, float]) – Per-qubit T1 (longitudinal relaxation) in nanoseconds. Keys are qubit indices. Missing qubits default to float("inf").

  • t2 (dict[int, float]) – Per-qubit T2 (transverse relaxation) in nanoseconds. Keys are qubit indices. Missing qubits default to float("inf").

  • gate_errors (dict[str, float]) – Per-gate-type average error rate (probability), e.g. {"cx": 0.005, "sx": 0.0003}.

  • coupling_edges (list[tuple[int, int]]) – List of (q0, q1) pairs indicating connected qubit pairs.

  • gate_times (dict[str, float]) – Per-gate-type average duration in nanoseconds, e.g. {"cx": 350.0, "sx": 35.0}.

to_noise_model(t_gate_ns=None)[source]¶

Convert calibration to a QuantX ThermalRelaxationNoise.

Uses the mean T1/T2 over all qubits. If T2 > 2·T1 (violates the Lindblad bound) it is clamped to 2·T1.

Parameters:

t_gate_ns (float | None) – Gate duration in nanoseconds used to compute the per-gate damping parameters. Defaults to the calibration’s mean CX time, falling back to 50 ns.

class quantx_engine.hardware.IBMHardwareBackend(token=None, instance='ibm-q/open/main', backend_name='ibmq_qasm_simulator')[source]¶

Bases: object

Extended IBM Quantum backend with async submission, calibration fetching, and pulse-schedule submission.

This class wraps IBMQuantumBackend and adds:

  • submit() — non-blocking circuit submission returning a HardwareJob.

  • fetch_calibration() — pull T1/T2/gate-error calibration from the IBM device properties API and return a BackendCalibration.

  • run_pulse() — submit a QuantX PulseSchedule to IBM as a native pulse job.

  • list_backends() — list available IBM backends for the configured instance.

Parameters:

  • token (str | None) – IBM Quantum API token. Falls back to QISKIT_IBM_TOKEN env var.

  • instance (str) – IBM Quantum instance string ("hub/group/project").

  • backend_name (str) – Target backend name.

quantx_engine.hardware.calibration_to_noise_model(calibration, t_gate_ns=None)[source]¶

Convert a BackendCalibration to a QuantX noise model.

Uses BackendCalibration.to_noise_model(). If significant depolarizing gate error is present (max gate error > 0.1 %) a CompositeNoise combining DepolarizingNoise with the thermal relaxation model is returned.

Parameters:

  • calibration (BackendCalibration) – Device calibration snapshot.

  • t_gate_ns (float | None) – Override gate duration in ns; defaults to the calibration value.

Return type:

NoiseModel

quantx_engine.hardware.available_backends()[source]¶

Scan environment variables and return a dict of available backends.

Checks for:

  • QISKIT_IBM_TOKEN → IBM backends (uses "ibmq_qasm_simulator" as placeholder; real backend list requires a live connection).

  • IONQ_API_KEY → IonQ backends (simulator always available).

  • GOOGLE_CLOUD_PROJECT → Google backends (simulator always available).

Return type:

dict mapping provider name to list of backend name strings.
